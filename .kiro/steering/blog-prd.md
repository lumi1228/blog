## 一、产品概述

### 1.1 背景与目标

**业务背景**
个人博客是开发者/内容创作者展示技术积累、输出思考、建立个人品牌的核心载体。相比第三方平台（掘金、CSDN、语雀），自建博客拥有完全的数据控制权、自定义设计能力，以及对 SEO 更友好的结构。

**核心目标**
| 目标 | 衡量指标 |
|------|---------|
| 快速发布/管理博客内容 | 单篇文章从撰写到发布 ≤ 3 步操作 |
| 读者获得良好阅读体验 | 首屏加载 ≤ 1.5s（LCP），文章页移动端可读 |
| 体现个人品牌 | 个人介绍模块信息完整，访客 3 秒内了解博主 |
| 内容可被搜索引擎索引 | 关键页面 SEO 分数 ≥ 85（Lighthouse） |

### 1.2 用户角色

| 角色 | 描述 | 核心诉求 |
|------|------|---------|
| **博主（管理员）** | 博客所有者，唯一可登录后台的人 | 快速写作、分类管理、统计数据 |
| **访客（读者）** | 通过搜索引擎或链接来访 | 快速找到感兴趣内容、流畅阅读 |

### 1.3 核心价值主张

- **现状**：内容散落在各平台，无法统一管理，样式受限
- **解决方案**：自建博客系统，统一写作、发布、展示
- **改变后**：拥有个人品牌阵地，内容资产完全自控
- **替代方案**：掘金/语雀（无自定义能力）、WordPress（技术栈不匹配）

## 四、详细功能说明

### 4.1 登录 & 鉴权模块

**功能描述**
管理员通过用户名+密码登录，获取 JWT Token，凭 Token 访问后台管理界面。

**主流程**
```
1. 访问 /admin/login
2. 输入账号密码 → 点击「登录」
3. 服务端校验 → 返回 JWT（存入 httpOnly Cookie）
4. 跳转 /admin/dashboard
```

**异常流程**
- 密码错误：提示「账号或密码有误」，不暴露具体哪个字段错误
- 连续 5 次错误：锁定 IP 15 分钟
- Token 过期：自动跳转登录页

**验收标准**
1. 正确账号密码登录后跳转后台
2. 错误密码不返回 200
3. 未登录用户直接访问 /admin/* 重定向到 /admin/login
4. JWT 存储在 httpOnly Cookie，不可通过 JS 读取

### 4.2 文章管理模块

#### 4.2.1 文章列表（后台）

**页面字段**：标题 | 分类 | 标签 | 发布状态 | 创建时间 | 操作（编辑/删除/切换发布状态）

**筛选&排序**
- 按分类筛选
- 按发布状态筛选（已发布/草稿）
- 按创建时间倒序（默认）

**批量操作**
- 批量删除（二次确认）
- 批量修改发布状态

#### 4.2.2 文章编辑器

**核心要求**
| 要求 | 说明 |
|------|------|
| 编辑器类型 | Markdown 编辑器（推荐：`@uiw/react-md-editor` 或 `tiptap`） |
| 实时预览 | 左侧编辑，右侧预览（桌面端双栏） |
| 代码高亮 | 支持主流语言（JS/TS/Python/Go 等），推荐 `shiki` |
| 图片上传 | 粘贴/拖拽图片自动上传，返回 URL 插入 |
| 自动保存 | 每 30s 自动保存为草稿，避免内容丢失 |

**文章元数据字段**
```
标题*         string     必填，≤ 100 字
摘要          string     选填，≤ 200 字（用于列表预览和 SEO description）
封面图        URL        选填
分类*         select     必选，单选
标签          tags       可多选，最多 5 个
发布状态      toggle     草稿/已发布
发布时间      datetime   默认当前时间，可设置定时发布
SEO 标题      string     选填，默认使用文章标题
SEO 描述      string     选填，默认使用摘要
```

**主流程**
```
1. 点击「新建文章」→ 打开编辑页
2. 填写标题 + 正文内容
3. 右侧填写元数据（分类/标签等）
4. 点击「保存草稿」或「发布」
5. 发布后跳转文章详情页预览
```

**验收标准**
1. 编辑器支持 Markdown 语法快捷键（Ctrl+B 加粗等）
2. 30s 自动保存，有「已保存」状态提示
3. 发布后文章在前台列表可见
4. 草稿不在前台列表显示
5. 删除需二次确认弹窗

### 4.7 SEO 模块

**技术实现**：利用 Next.js App Router 的 `generateMetadata` 函数，每个页面动态生成元数据

**每页必须包含**
```typescript
metadata = {
  title: string,            // [文章标题] | [博客名]
  description: string,      // 摘要或自定义描述
  openGraph: {
    title, description,
    images: [封面图URL],
    type: "article" | "website"
  },
  twitter: { card, title, description, image },
  alternates: { canonical: URL }
}
```

**结构化数据**：文章页注入 `Article` Schema（JSON-LD）

## 七、技术选型及版本说明

> ⚠️ 开发时必须使用对应版本的 API 和语法，避免使用已废弃或不兼容的写法。

### 7.1 核心技术栈（已锁定）

| 技术 | 版本 | 关键语法说明 |
|------|------|-------------|
| **Next.js** | `16.2.3` | App Router（非 Pages Router）；使用 `generateMetadata` 导出 SEO；Route Handlers 在 `app/api/` 下；Server Components 为默认，客户端组件需 `"use client"` 指令 |
| **React** | `19.2.4` | 支持 `use()` hook、Server Components、`useFormStatus`、`useOptimistic`；`forwardRef` 不再需要（ref 作为普通 prop）；`ref` callback 支持 cleanup 返回值 |
| **TypeScript** | `^5` | 严格模式（strict: true）；使用 `satisfies` 操作符进行类型收窄 |
| **Tailwind CSS** | `v4` | 使用 `@theme inline {}` 定义设计 token（非 tailwind.config.js）；`@import "tailwindcss"` 替代旧版 `@tailwind` 指令；支持 CSS 变量直接在 `@theme` 中映射 |
| **Node.js** | `>=20.9.0`（Next.js 16 要求） | 使用 ES Modules |

### 7.2 数据层

| 技术 | 版本 | 说明 |
|------|------|------|
| **Supabase** | `@supabase/supabase-js ^2.103.0` | 数据库 + 认证；使用 Row Level Security (RLS) |
| **@supabase/ssr** | `^0.10.2` | Next.js App Router 集成；`createServerClient` / `createBrowserClient` |

### 7.3 补充依赖（按需安装）

| 类型 | 推荐方案 | 备选 |
|------|---------|------|
| **Markdown 编辑** | `@uiw/react-md-editor` | Tiptap |
| **MD 渲染** | `react-markdown` + `remark-gfm` | `marked` |
| **代码高亮** | `shiki` | `prism.js` |
| **客户端搜索** | `fuse.js` | - |
| **图片存储** | Supabase Storage | 本地 public 目录 |
| **评论系统** | Giscus（基于 GitHub Discussions）| Waline |

### 7.4 语法注意事项

**Next.js 16 App Router 要点：**
- 布局文件 `layout.tsx` 不可使用 `"use client"`，它是 Server Component
- 页面默认为 Server Component，需要交互时才加 `"use client"`
- 数据获取直接在 Server Component 中 `await`，无需 `getServerSideProps`
- 动态路由使用 `[slug]` 文件夹命名
- API 路由使用 `route.ts` 导出 `GET`/`POST`/`PUT`/`DELETE` 函数
- `metadata` 或 `generateMetadata` 只能在 Server Component 中导出
- `loading.tsx` / `error.tsx` / `not-found.tsx` 为约定式文件

**React 19 要点：**
- `ref` 作为普通 prop 传递，不再需要 `forwardRef`
- `use()` hook 可在条件语句中使用，用于读取 Promise 和 Context
- `<form action={serverAction}>` 支持 Server Actions
- `useFormStatus()` 获取表单提交状态
- `useOptimistic()` 实现乐观更新

**Tailwind CSS v4 要点：**
- 入口文件使用 `@import "tailwindcss"` 而非 `@tailwind base/components/utilities`
- 自定义主题通过 `@theme inline {}` 在 CSS 中定义，不再使用 `tailwind.config.js`
- 支持 CSS 变量直接映射：`--color-primary: var(--my-var)`
- 新增容器查询、`@starting-style`、`light-dark()` 等现代 CSS 特性支持

## 九、非功能需求

| 维度 | 要求 |

| SQLite 并发能力 | 低 | 中 | 个人博客流量小，无需担心；若上量迁 Postgres |
| 数据备份丢失 | 低 | 高 | 定期导出 SQLite 文件或用 Vercel Postgres 自动备份 |
| 后台暴露在公网 | 中 | 高 | /admin/* 严格 JWT 鉴权 + 可配置 IP 白名单 |
