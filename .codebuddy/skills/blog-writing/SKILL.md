# Zerone 技术博客写作规范

为 Zerone 项目撰写技术博客时遵循本规范。博客既是学习沉淀，也是可对外发布、面试可讲的作品，读者是其他开发者。博客默认放在 `.docs/blog/`，`.md` 格式。

## 一、标题

1. **标题必须包含该篇覆盖的核心功能/能力**，让人一眼知道讲了什么。
   - 好：`项目脚手架 · 双层自动化测试 · CI · 自动部署与自定义域名`
   - 差：`Task 1 总结` / `项目初始化`（看不出内容）
2. **不要出现内部任务编号腔调**（如 "Task 1"、"第一个任务"）。系列用自然序号 `（一）(二)` 即可。
3. 用 `·` 或顿号串联多个核心能力，简洁不堆砌。

## 二、整体结构

按以下顺序组织，次要概念作为**子节**而非与核心模块平级的大节：

判断层级的原则：**平级大节留给本篇的核心能力；顺带理解的概念收作子节。**

**序号约定（适量）**：
- 主标题（`#`）带系列序号 `（一）(二)…`。
- 正文主要章节（`##` 级）适量加序号（`1.`、`2.`…）帮助读者建立顺序感。
- 收尾的「小结」「参考文档」可不编号；子节（`###`）一般不编号。
- 原则是"适量"——够建立顺序感即可，不层层嵌套编号（不写 `3.2.1` 这类）。

## 三、技术选型的写法

1. 用表格呈现：`层 | 技术 | 真正的优势`。
2. **理由必须写这项技术本身的真正优势**，而不是"与已有技术栈一致""大家都用""顺手"这类非理由。
   - 差：Tailwind —— 与博客同栈。
   - 好：Tailwind —— 原子化 utility，样式写在标签上免去命名与上下文切换；内置设计约束保证一致性；按需生成 CSS 体积小。
3. **技术选型表只放真正的"技术"**（框架、语言、库、工具）。包管理器、目录结构（`src/`）这类**工程约定**不属于技术选型，单独拎成一段"工程约定"说明，不要混进技术表。

## 四、代码块规范

1. 每段代码块顶部用注释标明**文件路径与作用**（如 `// vitest.config.ts —— Vitest 的运行配置`）。
2. **关键行加行内注释**，解释"为什么这么写"，而不仅是"这是什么"。尤其是配置文件、测试文件、易踩坑的写法。
   - 例：`exclude: [...configDefaults.exclude, "e2e/**"], // 保留默认排除项，再排除 e2e，否则 Vitest 会去跑 Playwright 用例而报错`
3. 代码取自项目**真实文件**，不虚构；片段保持可读长度，过长则截取关键部分。

## 五、原理讲解

1. 先讲"是什么、为什么"，再给代码。
2. 涉及流程/数据流/对比时，用表格或 mermaid 图辅助。
3. 面向核心能力的模块，点出对应的面试考点与标准答法（可放小结或独立"面试视角"）。

## 六、实操步骤与踩坑

1. **把真实操作步骤写清楚**：控制台点哪里、命令怎么敲、填什么值。
2. **踩过的坑要单独写出来**，包含：现象 → 根因 → 正确做法。这是博客最有价值的部分之一。
   - 例：域名不生效 → `dig NS` 发现 DNS 实际托管在 Cloudflare（注册商 ≠ DNS 服务商）→ 应在当前生效的 DNS 服务商加 DNS-only 的 CNAME，而非改 nameserver。
3. 给出可复制的验证命令（如 `dig @1.1.1.1 ... +short`）及预期输出。

## 七、底部参考文档

1. 文章**最底部**加 `## 参考文档` 模块。
2. 按**本篇各模块用到的库/工具**分组列出官方文档地址。
3. **有可靠中文文档的优先用中文**，并标注「中文」：
   - 官方中文优先（如 React `zh-hans.react.dev`、Vitest `cn.vitest.dev`、GitHub Actions `docs.github.com/zh`、TypeScript `typescriptlang.org/zh`）。
   - 官方无中文时，可用成熟社区中文镜像（如 `next.nodejs.cn`、`playwright.nodejs.cn`、`tailwindcss.cn`），并**并列官方英文地址兜底**（镜像可能滞后）。
   - 确无可靠中文的用官方英文（如 Testing Library、ESLint、Vercel、Cloudflare）。
4. 链接要核实可用，不臆造 URL；不确定的中文文档地址先用 web 搜索确认。

## 八、语言与风格

- 中文撰写；技术术语可保留英文并配中文解释。
- 平实、准确、面向开发者，不堆形容词、不喊口号。
- 贯穿一条可复用的判断原则时点明（如"收益未出现前不引入额外复杂度"），增强说服力。
